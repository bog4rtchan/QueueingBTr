# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- Run: `node server.js` (env: `PORT`, default 3000; `HOST`, default `127.0.0.1`, set `0.0.0.0` for LAN/TV access; `CONTROL_PASSWORD`, required for `/action` whenever HOST is not localhost — without it a public server rejects all actions)
- Deploy: Render free web service (`node server.js`). `RENDER` (set by Render) makes HOST default to `0.0.0.0`. When `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` are set, state is stored in Upstash Redis (key `queue-state`, via `fetch` to the REST API, no SDK) instead of `state.json`; a failed load exits the process rather than starting empty.
- Test: `node test.js` (plain `node:assert` script covering `queue.js`; no test runner, no single-test selection)

Node 18+, zero dependencies, no build step. `package.json` exists only so hosts detect a Node app (`npm start`); keep it dependency-free.

## Architecture

Two-queue ticket system (A = ATAP Issuance, C = CL Issuance). A PC runs `control.html`; a TV shows `display.html`.

- `queue.js` — pure reducer `apply(state, {queue, type})` returning new state; throws on bad input (server maps that to 400). State per queue is `{issued, serving, counter, calls, line, skipped, missing}`; `missing` are lost stubs, per queue: `add` jumps over them, marking removes them from `line`/`skipped`, unmarking doesn't re-add them, `insert` rejects them, and `reset` keeps the list; `counter` (1–3, 0 = none) is the counter the on-screen number was called to — `next` requires `counter` in the action and stores it, `recall` keeps it. `line` is the explicit waiting order (so re-added numbers can go first), `skipped` are numbers taken out of it. Older saved state has only counters; `normalize()` rebuilds `line` from `serving+1..issued` minus `skipped`, so always go through it. Top level also has `voice` (`Valkyrie`|`Halliday`, set by the queue-less action `{type:'voice', voice}`; `view` defaults it for old state). Top level `history` logs every queue action as `{at, queue, type, number?, counter?}` (type is the action type, except `unskip`/`found` for the toggle-off direction of skip/missing), capped at 2000; `apply` takes `now` as a third argument (server passes `Date.now()`), no-ops (Call with nobody waiting, Repeat with nothing on screen) return the same state and aren't logged, and `reset` keeps the log. `previous` (per queue, capped 50, cleared by `reset`) is a stack of earlier `{number, counter}` calls pushed by `next`; `back` pops it, puts the current number at the front of `line`, bumps `calls` (so the TV announces) and logs `returned`. `view(state)` omits `history` (served by `GET /history` instead, since `/state` is polled every second) and exposes `line` as `waiting`, which is what the pages read. `insert` puts a specific number in: below `serving` → front (behind earlier re-added passed numbers), otherwise number order; a number above `issued` bumps `issued` so Issue never duplicates it. Ticket labels (A7, C12) are derived from these counters, not stored.
- `server.js` — plain `node:http`. `GET /state`, `GET /history` (public, read-only), `POST /action` (body `{queue, type}`, type ∈ add/next/recall/reset/skip/insert/missing; skip, insert and missing also need `number`; next needs `counter` 1–3; skip and missing toggle), everything else is static from `public/` (path-traversal guarded). `/action` checks the `X-Control-Password` header against `CONTROL_PASSWORD`; the control page stores it in localStorage and shows an unlock bar on 401. `/state` and the display stay public. State is loaded once before `listen` and saved after every action (`state.json` locally, Upstash in the cloud); saves are chained so they land in order, and a failed save is logged, not fatal.
- `public/control.html` — sends actions only (no audio). Polls `/state` every 1s (skipped while the tab is hidden) so several open panels stay in sync; all updates go through `setState()`, which redraws only when the JSON changed (a redraw rebuilds the dropdown and chip lists) and `render()` restores keyboard focus. Each queue has a Counter 1/2/3 radio group; Call is disabled until one is chosen, and the choice is kept in localStorage (`counterA`, `counterC`).
- `public/history.html` — read-only page: polls `GET /history` every 2s (skipped while hidden), redraws only on change, and replays the event log into one row per ticket, in a separate table per queue (Issued / On queue / Called circles, red when skipped or still waiting at Start over; summary cards count the round since the last Start over; `back` returns the `returned` ticket to not-called; missing stubs are dropped). One section (card + table) per queue. Linked from the control header.
- `public/display.html` — polls `/state` every 1s and **plays the audio**. It detects a new call by `calls` changing (which is why `recall` bumps `calls` without changing `serving`), then slides the number in and announces it. Browsers block autoplay, so the page starts behind a full-screen "Turn on sound" button; that click unlocks audio for the page. Announcements are chained clips read digit by digit: `chime → Now Serving → Authority to Accept Payment|Confirmation Letter → A|C → digits → Counter1|2|3`, loaded from `public/audio/<voice>/<name>.wav` (voice from `/state`; `chime.wav` stays in `public/audio/`) (names have spaces and capitals, matching the user's recordings; ATAP = Authority to Accept Payment, CL = Confirmation Letter). Missing clips are skipped and reported in the page.
- `public/style.css` — shared colour/font tokens for both pages. Each queue has one colour (`.lane-A` blue, `.lane-C` marigold) used on both screens. Fonts are self-hosted in `public/fonts/` so the system works offline; don't switch to a font CDN.


`state.json` is runtime data, not config.
